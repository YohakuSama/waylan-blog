# Waylan 核心页面的内容型视觉系统（2026-11-07）

## 先判断，再修改

基线为 main@76a4d26（PR #154 已合并）；PR #155 是未完成的布局实验，不能作为新的设计基线。截图问题并非“每个页面都必须 960px”，而是五个一级页**没有统一的信息层级和布局角色**：内容页的筛选看起来像单独的卡片、项目被排成普通文章流、归档活动图占据主任务之前的大段空间、关于页的站点事实藏在文章末尾。存在有意差异：长文需要较短行宽，项目需要能比较的项目展示方式，而归档本质是时间序列。

### 核查的设计来源（各取其法，不复制品牌样式）

- BBC GEL [Grid](https://bbc.github.io/gel/foundations/grids/) 与 [Typography](https://bbc.github.io/gel/foundations/typography/)：稳定视觉栅格、适度行宽、标题与其所属内容之间的距离应该小于栏目之间的距离；同时保障 DOM 阅读顺序。
- Apple [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：内容的相对重要性决定位置；对齐与分组表达关系，屏幕变小时不是简单缩小桌面。
- GitHub Primer [Layout](https://primer.style/product/getting-started/foundations/layout/)：Header / Content / Pane 各有职责；右侧 Pane 用于上下文信息，移动端次要信息可接在主内容后，但不能无故隐藏。
- [Antfu Posts](https://antfu.me/posts)：年份、日期、文章标题构成可以快速浏览的技术写作时间线。
- SpaceX [Launches](https://www.spacex.com/launches)：项目/任务类型的数据优先显示状态、分类、时间和后续入口，而不是把任务记录等同于普通文章。

参考用于信息组织和行为，不复制 BBC、WSJ、Bing、Apple 或 SpaceX 的视觉资源、品牌配色及复杂广告/营销模块。WSJ 与 Bing 的具体栏目变化没有逐版本验证，不能宣称完成逐像素对标。

## 页面任务、组件价值及屏幕策略

| 页面 | 首要任务 / 内容顺序 | 组件的存在理由及处理 | 桌面 / 平板 / 手机 |
| --- | --- | --- | --- |
| 首页 Home | 简介 → 有进度时继续阅读 → 最新内容 → 辅助发现 | `FeedList` 为统一帖子数据渲染；`TopicsBlock` 与真实项目提供探索；`NetworkWave` 是有限装饰。**保留全部**；继续阅读无记录时不伪造卡片 | 桌面 1140px 主栏＋发现侧栏；平板主题在文章前；手机以文字文章优先，装饰仅在合适屏宽展示 |
| 内容 Feed | 内容类型 → 主题 → 排序 → 结果数量／显示模式 → 列表 | `TypeTabs`、原生移动选择器、`ViewToggle`、标签链接与 URL 筛选参数都是功能，不删不重复 | 桌面把操作分组为有标题的编辑工具行；小屏仍用原生选择器；结果与操作保持单一视觉区域 |
| 归档 Archive | 年份/月份/日期列表 → 统计性的发布节奏 | `Heatmap` 真实统计 16 周；保留但降为补充信息，不放在时间轴之前阻挡首屏。年月、类型标签都保留 | 桌面用主时间线与次要活动栏，年/月标签使用结构化时间轴；平板/手机先读年份条目、最后查看活动图 |
| 项目 Projects | 项目名称/状态 → 简介 → 真实技术栈及外链 | `FeedList` 仍负责列表数据和收藏；`project-thumb` 的缩略信息、真实标签/外链都保留。展示布局随页面角色变，不复制首页的文章封面 | 桌面 2 个可比较的项目展示单元；平板/手机改为单列，不隐藏状态、标签或入口 |
| 关于 About | 作者/博客介绍 → 阅读正文及联系 → 技术与站点事实 | `site.aboutHtml` 为完整已消毒正文；`SocialList`、`SiteStats` 为已有功能；`about-motto` 是独立引用，不删 | 桌面正文保留 720px 阅读行宽，技术及数据作为右侧注解；小屏资料在正文后，引用维持独立但减轻卡片感 |

## 全站共同规则

1. 版心统一为 `--index-frame-width`；页眉及阅读页 Logo 位置使用**同一套**宽度约束，避免 #155 出现的 desktop 1280px Logo 左边界回归。
2. **一个功能，一个组件所有者**。`shell.css` 负责头部和 Home，`site.css` 负责页容器、归档/关于/内容检索，`feed.css` 负责项目等卡片表现，`responsive.css` 负责断点，`skins.css` 只负责四种皮肤的配色/装饰。
3. 链接、按钮及次级信息复用现有字体、颜色和 40/44px 触控尺寸。装饰不改变阅读顺序，不因布局修复隐藏真实功能。
4. 视觉测试同时核对**信息流顺序、内容层级、主辅栏关系**，而不只是左右坐标与最大宽度。
5. 应覆盖 1440/1024/768/390/320px，editorial/terminal × light/dark，含有进度/无进度、筛选状态、项目两条和归档活动数据。自动化截图必须人工抽查，不能用“CI 通过”代替设计验收。

## 验收边界与回滚

- 不修改 Worker、鉴权、评论、数据源、项目真实外链、路由、阅读记录策略或数据格式；无需数据库迁移。
- 不强制所有页面具有相同组件个数/内容宽度。项目网格和归档时间轴的差异是**刻意的功能差异**。
- 相关测试必须通过，且需人工审视典型 1440/768/390 截图，看文字对比、层级、间距和组件位置。测试失败时停止合并；布局不达标即使构建通过也停止合并。
- 合并采用 squash，发现问题可以 revert 合并提交；回滚仓库源码与 Cloudflare 生产回滚是不同动作。
